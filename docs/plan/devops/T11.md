- ชื่อฟังก์ชัน: - (ไม่มีฟังก์ชัน) `Dockerfile`, `docker-compose.yml`
- สิ่งที่ต้องทำ: `Dockerfile` multi-stage: stage `node:24-slim` รัน `npm ci && npm run build` ใน `frontend/` → stage `python:3.14-slim` ติดตั้ง `backend/requirements.txt`, copy `backend/app` และ `frontend/dist` ไป `/app/static`, ตั้ง `STATIC_DIR=/app/static`, `DATABASE_PATH=/data/todo.db`, สร้าง `/data` ให้ user non-root เป็นเจ้าของ, `USER` non-root, `CMD uvicorn app.main:app --host 0.0.0.0 --port 8000` · `.dockerignore` ตัด `.venv`, `node_modules`, `dist`, `*.db`, `.git`, `e2e` · `docker-compose.yml` service `todo`: build `.`, ports `127.0.0.1:8000:8000` (ให้ reverse proxy บน VPS เป็นทางเข้าเดียว), volume `todo-data:/data`, `restart: unless-stopped` · README ตาม Produces · เพิ่ม job `docker` ใน CI รัน `docker compose build`
- ไฟล์ที่แก้: Dockerfile, .dockerignore, docker-compose.yml, README.md, .github/workflows/ci.yml
- Produces: `docker compose up -d --build` → หน้าเว็บ + API ที่ `http://127.0.0.1:8000` บน VPS · ข้อมูลอยู่ที่ `/data/todo.db` ใน volume `todo-data` · `README.md`: วิธีรัน dev, รันเทสต์, deploy บน VPS · ตัวอย่าง config reverse proxy (Caddy หรือ nginx) ที่ทำ HTTPS และจำกัดขนาด body ไม่เกิน 64 KB (`request_body { max_size 64KB }` / `client_max_body_size 64k`) · บอกว่า compose bind แค่ `127.0.0.1` ต้องเข้าผ่าน proxy
- Uses from earlier tasks: env `STATIC_DIR`: ถ้าตั้งไว้ `GET /` ได้ `index.html` และไฟล์ใต้โฟลเดอร์นั้นเสิร์ฟเป็น static ส่วน `/api/*` ทำงานเหมือนเดิม · ไม่ตั้ง → ไม่เสิร์ฟหน้าเว็บ · ตั้งแต่โฟลเดอร์ไม่มี → app start ไม่ขึ้น (T10) · `create_app(db_path: str, static_dir: str | None = None) -> FastAPI` และ `app = create_app(os.environ.get("DATABASE_PATH", "todo.db"), os.environ.get("STATIC_DIR"))` (T10) · คำสั่งติดตั้ง / เทสต์ทั้งชุด / lint / build ของ backend, frontend, e2e ตามตาราง "คำสั่ง" ใน `docs/architecture.md` รันได้และผ่าน (ยังไม่มีเทสต์จริง) (T1) · `.github/workflows/ci.yml`: `permissions: contents: read` · job backend (ruff + pytest + `pip-audit -r requirements.txt`), frontend (npm test + npm run build + `npm audit --omit=dev`), e2e (`npx playwright test --pass-with-no-tests`) รันทุก push และ pull request (T1)
- ผลที่ต้องได้: `docker compose up -d --build` แล้ว `/` ได้ 200 HTML ของหน้าเว็บ และ `/api/todos` ได้ 200 JSON · เพิ่ม todo แล้ว `docker compose down && docker compose up -d` → todo ยังอยู่ · process ใน container ไม่ใช่ root · port 8000 bind แค่ `127.0.0.1` · README มีวิธีรันบน VPS + ตัวอย่าง proxy ที่จำกัด body 64 KB · CI มี job docker
- วิธีตรวจงาน: `docker compose up -d --build && sleep 3 && curl -fsS -o /dev/null -w "%{http_code}\n" http://localhost:8000/` → `200` · `curl -fsS http://localhost:8000/ | grep -i "<div id=\"root\">"` → เจอ · `curl -fsS -X POST -H "Content-Type: application/json" -d "{\"title\":\"persist\"}" http://localhost:8000/api/todos` → 201 · `docker compose down && docker compose up -d && sleep 3 && curl -fsS http://localhost:8000/api/todos | grep persist` → เจอ · `docker compose exec todo id -u` → ไม่ใช่ `0` · `docker compose port todo 8000` → `127.0.0.1:8000` · `grep -nE "64KB|64k" README.md` → เจอ · `docker compose down -v` (ล้างหลังตรวจ) · `grep -n "docker:" .github/workflows/ci.yml` → เจอ
