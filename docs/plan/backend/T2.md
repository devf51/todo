- ใครเป็นคนทำ: backend
- ชื่อฟังก์ชัน: `create_app()`, `init_db()`, router `/api/todos` → `GET` / `POST /api/todos`, `PATCH` / `DELETE /api/todos/{id}`
- สิ่งที่ต้องทำ: สร้าง schema ทั้ง 2 ตาราง (`categories`, `todos`) ตามหัวข้อ "ข้อมูล" ใน architecture ทุกคอลัมน์ ด้วย `CREATE TABLE IF NOT EXISTS` ตอน `create_app()` · ทุก connection เปิด `PRAGMA foreign_keys = ON` · connection ใหม่ต่อ request · ทำ 4 endpoint ตาม Produces: title ตัดช่องว่างหน้าหลังก่อน validate 1–200 ตัวอักษร · path id ใช้ `Path(ge=1, le=2**63-1)` (เลขเกิน int64 ทำให้ `sqlite3` โยน `OverflowError` → 500) · PATCH แก้เฉพาะ field ที่ส่งมา (`title` ถูก validate แบบเดียวกับ POST, `null` ของ `title` / `done` → 422, body `{}` → 200 คืนค่าเดิมโดยไม่รัน UPDATE) · ชื่อคอลัมน์ใน `SET` มาจาก whitelist คงที่ของ model เท่านั้น ห้ามใช้ key จาก body · SQL ใช้ placeholder `?` เท่านั้น · ยังไม่รับ `due_date` / `priority` / `category_id` จาก body (field เกินถูกเมิน) แต่ส่งกลับใน `Todo` ด้วยค่าเริ่มต้น
- ไฟล์ที่แก้: backend/app/__init__.py, backend/app/main.py, backend/app/db.py, backend/app/todos.py, backend/tests/conftest.py, backend/tests/test_todos.py
- Produces: `GET /api/todos` → `200 Todo[]` เรียงตาม id น้อยไปมาก · `POST /api/todos` body `{title: string}` (ตัดช่องว่างหน้าหลัง, 1–200 ตัวอักษร) → `201 Todo` · `422 {detail}` ถ้า title ว่าง / มีแต่ช่องว่าง / ยาวเกิน 200 · `PATCH /api/todos/{id}` body `{title?: string, done?: bool}` → `200 Todo` (body `{}` → 200 ค่าเดิม, `title: null` / `done: null` → 422) · `404 {detail: "todo not found"}` · `422 {detail}` · id ใน path นอกช่วง 1..9223372036854775807 → `422 {detail}` · `DELETE /api/todos/{id}` → `204` · `404 {detail: "todo not found"}` · id ใน path นอกช่วง 1..9223372036854775807 → `422 {detail}` · `Todo = {id: int, title: string, done: bool, due_date: string|null, priority: "low"|"medium"|"high", category_id: int|null}` (ค่าเริ่มต้น `due_date: null`, `priority: "medium"`, `category_id: null`) · `create_app(db_path: str) -> FastAPI` ใน `backend/app/main.py` และ `app = create_app(os.environ.get("DATABASE_PATH", "todo.db"))` · fixture `client` (TestClient บน DB ชั่วคราวใน `tmp_path`) ใน `backend/tests/conftest.py`
- Uses from earlier tasks: none
- ผลที่ต้องได้: `POST /api/todos` `{"title":"ซื้อนม"}` → 201 `done: false`, `due_date: null`, `priority: "medium"`, `category_id: null` และเห็นใน `GET` · title ว่าง / `"   "` / 201 ตัวอักษร → 422 และ `GET` ยังมีจำนวนเท่าเดิม · title มีช่องว่างหน้าหลังถูกตัด · `PATCH` `done: true` / `done: false` / `title` ใหม่ → 200 ค่าตามนั้น และ `GET` เห็นค่าใหม่ · `PATCH` title ว่าง / `title: null` / `done: null` → 422 · `PATCH {}` → 200 ค่าเดิม · id `0` หรือเกิน int64 → 422 · `DELETE` → 204 แล้ว `GET` ไม่มี · `PATCH` / `DELETE` id ที่ไม่มี → 404 `{"detail": "todo not found"}` · ข้อมูลอยู่รอดเมื่อสร้าง `create_app()` ใหม่บนไฟล์ DB เดิม

## แผนแก้รอบ 1 (tech-lead)
- ที่มา: qa F2 รอบ 1
- ปัญหา: backend ตอบ 500 / connection reset เมื่อมี request พร้อมกัน เช่น `POST /api/todos` 30 ตัวพร้อมกัน (e2e `F1 API › concurrent POST /api/todos all return 201`) ทำให้ชุด e2e ขนานล้มสุ่ม · log: `sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread`
- ยืนยันแล้ว: รัน uvicorn จริงบน DB ชั่วคราว ยิง `POST /api/todos` 300 ครั้งด้วย 30 thread → โค้ดปัจจุบัน `Connection reset by peer`; เปลี่ยน `sqlite3.connect(db_path)` เป็น `sqlite3.connect(db_path, check_same_thread=False)` ในสำเนานอก repo → `{201: 300}`
- สาเหตุ: `get_conn` (backend/app/todos.py:55-61) เป็น sync generator dependency FastAPI รันส่วนก่อน `yield` และส่วนหลัง `yield` (`commit()` / `close()`) ใน threadpool thread คนละตัวได้ แต่ `connect()` (backend/app/db.py:20) ใช้ค่าเริ่มต้น `check_same_thread=True` จึง error เมื่อ thread ไม่ตรง · connection ใหม่ต่อ request และใช้ทีละ request เท่านั้น ไม่มี thread สองตัวใช้ connection เดียวพร้อมกัน จึงปิดการตรวจนี้ได้อย่างปลอดภัย
- สิ่งที่ต้องแก้: ใน `connect()` ส่ง `check_same_thread=False` (แก้ที่เดียว ใช้ร่วมกับ `categories.py` ของ T6 อยู่แล้วผ่าน `Conn`) ไม่เปลี่ยน `Produces:` · เขียนคอมเมนต์สั้นบอกเหตุผล (connection ต่อ request, ไม่แชร์ข้าม request)
- เทสต์ที่ต้องเห็น fail ก่อน: `test_concurrent_requests_all_succeed` ใน `backend/tests/test_todos.py` — `TestClient` ธรรมดาไม่ reproduce (รันใน thread เดียว) ให้เปิด uvicorn จริงบน `tmp_path` DB ผ่าน subprocess บน port ว่าง (หรือ `uvicorn.Server` ใน thread) แล้วยิง `POST /api/todos` 30 ตัวพร้อมกันด้วย `ThreadPoolExecutor` + `httpx` คาด 201 ทั้งหมดและ `GET` ได้ 30 รายการ · ก่อนแก้ต้องเห็น fail (500 / connection error) ถ้าไม่ fail ให้เพิ่มจำนวนรอบ (เช่น 300 ครั้ง) จนเห็น fail ก่อนแก้โค้ด
- ไม่แก้: เทสต์ e2e `concurrent POST` ของ qa ใช้ต่อได้ตามเดิม ไม่ต้องแก้
