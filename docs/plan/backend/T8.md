# T8 — ตัวกรองรายการ todo
- ใครเป็นคนทำ: backend
- ชื่อฟังก์ชัน: query `status`, `category_id`, `priority` ของ `GET /api/todos`
- สิ่งที่ต้องทำ: เพิ่ม query parameter ตาม Produces: validate ด้วย enum / int ของ FastAPI (ค่าผิด → 422) · ประกอบ `WHERE` จากรายการเงื่อนไขคงที่ ค่าทั้งหมดส่งเป็น placeholder `?` · ไม่เปลี่ยนการเรียง
- ไฟล์ที่แก้: backend/app/todos.py, backend/tests/test_todos.py
- Produces: `GET /api/todos?status=all|active|done&category_id=<int>&priority=low|medium|high` (ทุกตัวไม่บังคับ, ไม่ส่ง status = all, หลายตัวรวมกันแบบ AND, category_id ที่ไม่มีได้ `[]`) → `200 Todo[]` เรียงแบบเดิม · `422 {detail}` ถ้าค่าไม่ถูกต้อง
- Uses from earlier tasks: `GET /api/todos` → `200 Todo[]` เรียง `due_date` น้อยไปมาก, `due_date: null` อยู่ท้าย, เท่ากันเรียงตาม id (T4) · `POST /api/todos` และ `PATCH /api/todos/{id}` รับ `category_id?: int|null` เพิ่ม (`null` = ไม่มีหมวด) → `422 {detail: "category not found"}` ถ้าไม่มีหมวดนั้น (T6) · fixture `client` (TestClient บน DB ชั่วคราวใน `tmp_path`) ใน `backend/tests/conftest.py` (T2)
- ผลที่ต้องได้: `?status=active` ได้เฉพาะ `done: false` · `?status=done` เฉพาะ `done: true` · ไม่ส่ง / `?status=all` → ทั้งหมด · `?category_id=<id>` เฉพาะหมวดนั้น · `?priority=high` เฉพาะ high · `?status=active&priority=high&category_id=<id>` → ตรงทุกเงื่อนไข · `?status=xxx`, `?priority=xxx`, `?category_id=abc` → 422 · `?category_id=999` → `[]`
- วิธีตรวจงาน: `cd backend && .venv/bin/pytest -v && .venv/bin/ruff check .` → ผ่านทั้งหมด และมีเทสต์อย่างน้อย: `test_filter_status_active_done_all`, `test_filter_category`, `test_filter_priority`, `test_filter_combined`, `test_filter_invalid_values_422` (parametrize 3 ค่า), `test_filter_unknown_category_empty`
