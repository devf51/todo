## รอบ 1
### ทำไปแล้ว
- `createTodo` / `updateTodo` รับ `due_date?`, `priority?` เพิ่ม (type เท่านั้น ตัว request ส่ง JSON.stringify เดิม)
- ฟอร์มเพิ่ม + ฟอร์มแก้ไขมี "วันกำหนดส่ง" (`type="date"`) และ select "ความสำคัญ" (ต่ำ/ปานกลาง/สูง → ค่า low/medium/high, ค่าเริ่มต้น medium) ผ่าน component `DueAndPriority`
- แต่ละรายการแสดง "ครบกำหนด <วันที่> · ความสำคัญ: <ไทย>" (ไม่มีวันที่ → ไม่แสดงส่วนครบกำหนด) ใช้ลำดับจาก API ไม่เรียงเอง
### ตัดสินใจ
- เพิ่ม: ส่ง `{title, due_date: due || null, priority}` เสมอ; แก้ไข: ส่ง `{title, due_date, priority}` เสมอ (ช่องวันที่ว่าง = `null`)
- หลังเพิ่มสำเร็จ ล้างช่องวันที่และคืน priority เป็น medium
- ช่องในฟอร์มแก้ไขใช้ label "วันกำหนดส่ง"/"ความสำคัญ" เหมือนฟอร์มเพิ่ม (แยก id ด้วย prefix) เทสต์จึงหาด้วย `within(li)`
- แก้ assertion เดียวของเทสต์ T3 (POST body `toEqual {title}` → `toMatchObject {title}`) เพราะ body มี field เพิ่มตาม T5 พฤติกรรมที่เทสต์ตรวจยังเหมือนเดิม
